Add-question dialog POC: the shipped picker renders one row per version, ships the whole library to the browser and filters it client-side, which does not hold up against a library of several hundred questions. Both variants below assume a server-side search endpoint instead, with result counts, pagination and type/status filters shown as though they are server-driven. The open question this POC is meant to settle is whether adding a question at its latest published version, shown on the row and changeable right up until the moment of adding, sits comfortably next to a pin's promise that nothing upgrades a chosen version automatically afterwards, or whether that visible default reads as tension with it. Use the toggle below to compare a strict one-question-at-a-time flow against a multi-select flow and judge which reads more clearly.

Variant: Strict picks one question, then one version in a radio group, then adds. Multi-select checks several questions at once, each with its own inline version choice, then adds them together.
