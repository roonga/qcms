# Agent builder: rulings and work plan

Status: Code Owner rulings recorded 2026-11-08 (Q1 to Q13) and 2026-11-13 (Q14 to Q21, with the security-review fixes). Nothing built. Source: the "QCMS Agent Builder" Design canvas and an independent review against `origin/main` (ff3952e7).

## Rulings

### Q13: entry and exit (Code Owner, 2026-11-08, revised 2026-11-12)

- The agent builder is a parallel screen and mode, like Operations. It does not change the standard assistant (the docked assistant) in any way.
- Two entry points, both behind the agent flag:
  - The New form screen offers "Start blank" (today's flow) or "Build with the assistant", which opens the builder with an empty form.
  - A form's menu gets "Edit with the agent builder", which opens the builder on that form's open draft.
  - There is no top bar start screen and no standalone top bar entry. Flag off: both entries are absent and the route is 404.
- Routes: `/forms/[formId]/build` for an existing form, `/forms/new/build` for a new form (no id until the first confirmed step).
- A new form is created lazily: the form and its first draft are created when the first step is confirmed, not when the builder opens, so abandoned sessions leave nothing. Until then Share preview and Publish are off.
- An existing form edits the open draft only, never a released version. A form with no open draft first offers "Start a new draft", as the publish wizard does.
- Publishing stays in the publish wizard, which takes a `returnTo` limited to the build screen.
- Authoring ignores the environment: no environment selector in the builder.
- Mode chrome, like Operations:
  - The top bar shows a group with the title "Agent builder", the form name (or "New form") and an Exit. No rail, no breadcrumb row.
  - The heading row holds Edit by hand, Share preview and Publish.
  - Below 64rem the assistant pane and the preview are two tabs.
  - Exit returns to where the user entered (the form or the New form screen). Edit by hand goes to `/forms/<id>`.
- The builder has its own conversation store, not shared with the docked assistant, and the dock does not render in the mode. The safety rule stays for everything except draft-scoped edits (Q14): an assistant proposal runs only from an ActionCard. This supersedes the earlier "one conversation store feeds the dock and the build pane".
- The existing manual builder and the docked assistant stay as they are.

## Review findings carried into the plan

- Logo storage does not exist. Raster only (PNG, JPEG, WebP), magic-number sniffed, size cap, SVG refused. Stored immutably and referenced by a theme, a draft and a version, so applying a theme copies it by value (`docs/WORKSPACE_ACCESS.md` section 9).
- Serve-step progress is only `{stepIndex, totalVisibleSteps}` (`apps/api/src/features/responses/serve-step/schema.ts`). The rail needs an ordered `steps` list.
- Measure layout in the admin browser and send it as a strict-schema fact. No `layout-report` API route.
- Put `data-qcms-question-id` on the qcms-owned wrapper in `packages/ui/src/form-field.tsx`, never on vendored files (ADR-22).
- Appearance goes inside the draft PUT body, not a second write route: one revision counter, one agent-assisted mark.
- Undo reverses the draft op only. Unpublished library versions stay until deprecated.
- "Tint the page background" changes every text-on-page pair. Include it in the contrast check or drop it.
- The builder shell needs a recorded exception to the one-rail rule in `plan/admin-design-contracts.md` section 7 and to the ruled panel widths in `apps/admin/lib/agent/panel.ts`.
- Respondents mid-session keep the version they started (ADR-07). Do not tell admins changes apply on next load.
- Use one word for rule-hidden steps: "Not needed".
- All new strings go in `apps/admin/lib/i18n/en.ts` and `apps/portal/lib/i18n/en.ts` (ADR-27).
- Mirror design rulings into the QCMS design system artifact in the same change.

## Security review requirements (2026-11-13)

W1 states these as requirements; the task named on each line builds them.

- **SEC-18 fetcher (A4).** `apps/api/src/features/webhooks/ssrf.ts` checks literals only and pins no DNS answer, so nothing there is reusable. The `BrandFetcher` port must:
  - check every A and AAAA record, mapped (`::ffff:`) and NAT64 forms included, and refuse if any is private;
  - connect to the pinned IP with SNI and certificate checks for the host;
  - allow port 443 only and refuse userinfo in the URL;
  - allow a content-type list and confirm it by magic-number sniff;
  - cap decompressed bytes and image pixels, and re-encode the logo;
  - send each subresource (CSS, logo) through the same guard, and redirects per Q19;
  - send no cookies;
  - answer every refusal with one uniform error, so it is no port-scan oracle.
- **Agent audit for edits (A6).** `control.agent_actions` rows are written today only from a verified proposal token (`apps/api/src/features/agent/audit.ts`). Each draft edit and each Undo needs a token-bearing route kind that writes its own row. The draft's `agentAssisted` field is client-supplied and is never trusted as evidence.
- **Lock (A2).** The workspace appearance lock is enforced by the draft PUT, not by the agent refusing. A2 depends on D2 for the lock column.
- **Logo route (A3).** Served to unauthenticated respondents with a fixed content type, `X-Content-Type-Options: nosniff`, and from the same origin, so SEC-9's `img-src` holds.
- **Docs W1 updates.** `docs/SECURITY_DESIGN.md`: the SEC count in the header and a SEC-18 row in the §10 control table. `docs/features/041-agent-form-building.md`: the tool allowlist line ("Never: publish, erase, mint links, webhook config") and the "multi-turn memory beyond the session" line, against Q14 to Q17.
- **Access spec.** The Q18 act rows go into `docs/WORKSPACE_ACCESS.md` on the access-spec branch through its owner; W1 depends on them and does not edit that branch.

### Required tests

- **Fetcher (X1, A4):** DNS rebinding; mixed public and private records; redirect refused, cross-site redirect refused, one same-site redirect re-validated; oversize body; slow body; gzip bomb; wrong content type; SVG or polyglot logo.
- **Injection (X4, G3):** a draft edit driven by library text cannot publish; each edit writes an audit row; a forged `agentAssisted` mark is not taken as provenance.
- **Authorisation (X3, U1, U7):** a View forms holder gets 404 or no tools on `/build`; create refused without Edit forms; a disabled account refused at Confirm; a PUT on a locked workspace refused; the open-wizard tool absent without Publish forms; the builder key set holds no publish, release, link or webhook kind.
- **Flag off:** both build routes 404; the derive route 404 with its own SEC-18 flag off and the agent flag on.
- **`returnTo`:** open-redirect cases refused (absolute URL, protocol-relative, another form's id, encoded slashes, a path other than `/forms/<id>/build`).
