Build an agent harness: QCMS form authoring

Domain: an assistant that helps administrators author questionnaires with conditional logic. Six phases, about five to six weeks. Write the loop yourself, with no SDK loop.

Learning project, not a rewrite. QCMS already has a production assistant in apps/api/src/features/agent, built on the AI SDK's streamText. This project builds the same architecture from the bottom up in a separate sandbox repo, so you understand the layer the SDK hides, then compare your result with the real one.

Why QCMS suits a harness

  • Immutability. Published form versions are frozen. A harness must never let the model touch them.
  • Determinism. The serving path has no LLM. The agent works at authoring time only, and everything it makes must pass the deterministic kernel.
  • Auditability. "What changed, who confirmed it, which prompt version proposed it" must be answerable.
  • A real validator. @roonga/qcms-core validates definitions and rules, so the harness has a ground truth to check the model against.

The workflow you will build

Model proposes a plan→ Kernel validates every step→ Card shows the full plan and verdict→ Human confirms→ Harness runs it as that user→ Human publishes separately

The boundary to design around

Model decides

  • Form structure: steps, question wording, order
  • The conditional logic that connects answers to next questions
  • Which library question to reuse instead of duplicating
  • How to explain the plan in two or three sentences

Harness and kernel enforce

  • Definition and rule validity (kernel verdict)
  • Tools offered = this user's permissions
  • The model never publishes; a human confirms every write
  • No access to respondent answers, ever
  • Step budget, tool allowlist, audit log

What you can say afterward

I built an agent harness from scratch for a questionnaire-authoring workflow. The model only proposes; a deterministic kernel validates every plan, tools are scoped to the signed-in user's permissions, a human confirms every write, and every turn is audited with its prompt version. I tested it with a scripted fake model and a scenario suite that includes prompt injection and stale-draft cases. Then I compared it with the AI SDK based assistant in the production codebase.
