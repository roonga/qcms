Learning project, not a rewrite. QCMS has an assistant in apps/api/src/features/agent, built on the AI SDK's streamText. The repo's README says QCMS is pre-release and not ready for production use, so call it "an open-source pre-release codebase" and never "production".

Why QCMS suits a harness

  • Immutability. Published form versions are frozen. Nothing the model does may change one.
  • Determinism. The serving path has no LLM. The agent works at authoring time only.
  • Auditability. QCMS defines this around what respondents were asked and answered. Your harness can extend it to cover agent actions, which production does only partly.
  • Authority without trust. The model holds no authority of its own. A human confirms each step, and the act runs as that person.

The workflow, as production actually does it

Model calls propose_plan→ Server checks each step (schema, grants, question and draft validators)→ Card shows every step and argument, plus the verdict→ Human confirms→ Client sends each step to the normal route with a signed, single-use token→ Route re-checks the user's permissions and the token

The assistant itself runs nothing. Publishing is an action kind the model can propose, removed from the schema if the user lacks the grant.

The boundary to design around

Model decides

  • Form structure: steps, question wording, order
  • The conditional logic between answers and next questions
  • Which library question to reuse
  • How to explain the plan

Harness enforces

  • Which tools and action kinds exist for this user
  • Plan validity before a human ever sees it
  • That a confirmed step is exactly what the card showed (signed token)
  • Single use, expiry, user and environment binding
  • No respondent answers in any tool output
  • Step, token and time budgets

Method: design first, then diff

  1. Before each phase, write a one-paragraph design of your own. Do not open the production code yet.
  2. Build it and test it.
  3. Only then read the matching production code and record every difference in DIVERGENCES.md, with the reason.

This turns "mirror production" into real design practice, and gives you interview answers about tradeoffs.

Phases

Using @roonga/qcms-core in a separate repo

  • It is not on public npm, is at version 0.0.0, and its dist is not built in a fresh checkout.
  • Build it in the QCMS repo, then use a file: dependency, a link, or a packed tarball. Pin it to a commit.
  • Useful exports: parseQuestionDefinition, parseFormDefinition, compileDraft, analyzeRuleGraph, checkRuleTypes, evaluateRules.
  • The kernel does not validate plans. You write the plan validator, and you reimplement question-version lookup and pin checks.
  • Fallback: a small zod-based mini-kernel of your own (questions, steps, a few condition operators). It keeps the focus on the harness, and costs about two days.

Live-model evals (real model, repeated trials)

These test the model plus your prompt and tools. Run each 10 or more times, record pass rate, steps and cost, and set a threshold. Never expect 100%.

What you can honestly claim afterward

I built a streaming tool-calling loop against the raw provider API for a propose, validate, confirm workflow. It has permission-scoped tools, signed single-use confirmation tokens, token-budgeted context with resumable sessions, and a scripted-model test suite plus repeated-trial live evals. I then compared my design with the AI SDK based assistant in an open-source pre-release codebase and documented where and why I diverged.

Avoid: "production", and "a kernel validates every plan".

Questions an interviewer may ask

  • Why write your own loop instead of using the SDK? (streaming, argument assembly and abort handling are the parts worth learning)
  • What happens when the context fills up mid-task?
  • How do you know a prompt change helped, given model variance?
  • How does prompt caching affect your design? (stable prefix, measured hit rate)
  • How do you stop a confirmed step from differing from what the user saw?
  • What do you do about a tool that has real side effects and fails halfway?
