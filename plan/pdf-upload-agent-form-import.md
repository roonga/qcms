# PDF upload for the authoring assistant: read a blank form, propose a QCMS form

Status: proposed, plan only (2026-11-23). Nothing is built and no decision below is ruled; every row marked "Code Owner" waits for a ruling. Checked against `origin/main` at `b849f6ab`. Source: the hands-on build of the course evaluation form (issue #1405) and the corpus in `docs/use-cases/`, which says it supplies sources "for future import, extraction and form-generation evaluations".

Governing records: `docs/agent-principle.md`, ADR-25 and its amendments (`docs/adr/admin.md`), SEC-17 (`docs/SECURITY_DESIGN.md` section 8d), SEC-13 (section 8a), `docs/agent-authoring.md`, `docs/agent-question-recipes.md`.

## Summary

An administrator attaches a PDF in the assistant panel. The assistant reads it and proposes a form (questions, options, steps, rules) as the cards it already uses. The administrator reviews and confirms; every act runs as them through the screen's own control. Nothing about serving a form changes, and no model sees respondent data.

Recommendations in one place (reasons in the decisions table):

- **Read the PDF with the provider's native PDF input, in a separate tool-less call** that returns a strict, bounded **document outline** (items, page, verbatim text, options, kind). No dependency, no parser in the API process, handles scans, keeps the untrusted document out of any context that holds tools.
- **The outline, not the PDF, drives the proposal turn.** The API signs the outline and the browser carries it (like the accept and edit tokens), so later turns still "have" the document, nothing is stored on the server, and the client can never inject unsigned content into the prompt.
- **Never persisted server-side.** The bytes live in memory for one request. No temp file, no database row, no provider Files API. The outline lives in the tab with the conversation and is cleared with it.
- **Upload through a new BFF multipart route that only streams to a new API route.** PDF handling is in the API, fetch-pure, on Web APIs alone. Not the assist JSON body: that would replay the file with every turn and hit the 1 MB body limit.
- **Behind its own flag, `QCMS_FLAG_AGENT_DOCUMENTS`, default off,** with a stricter rate class, because a document is sent to a third party and one read can cost tens of thousands of input tokens.
- **A new control, SEC-19,** for the new hostile-file inbound path and the new egress payload class, plus an ADR-25 amendment. The structural "respondent data never reaches the provider" guarantee cannot extend to a file the person chooses, so the wording changes and a warning ships with the control (conflict C1).
- **The corpus is not a side issue:** 7 of its 18 PDFs are encrypted, including the first one to evaluate, and 4 are XFA. The provider documentation says its PDF input takes no encrypted files. That is the first thing task 123 measures, before anything is built on it.
- **Per-question source line on the cards, rendered by the admin from the signed outline** (page and a quoted fragment), never from model words. Whole-plan Confirm stays; "drop this one" is a follow-up turn.
- **Evaluate against the corpus by manifest sha256,** report-only, never a gate. First three: course evaluation, WHO-5, NHS intake.

What this plan does not decide for the Code Owner is listed in "Open questions".

## Architecture

```
admin panel  --multipart-->  BFF POST /assist/document  --stream-->  API POST /admin/assist/document
 (attach)                    (flag, origin, session,                  (limits, magic bytes, limiter,
                              declared length; no parsing)             extraction call, audit row)
                                                                          |
                                                          generateText(file part + Output.object)
                                                          no tools, no history, document only
                                                                          |
admin panel  <--SSE: status... outline-ready{brief, items} / error--------+
 (holds brief)

next turns:  assist body { conversation, screen, params, ..., document: <brief> }
             API verifies the brief, puts it first in the model's messages, runs the existing loop
```

## The two stages

### Stage one: read

- Input: the PDF part and one fixed instruction. No conversation, no tools, no draft, no workspace content, no user text.
- Output: `Output.object({ schema: DocumentOutline })`, validated by Zod. A small local model that cannot do structured output falls back to a "reply with JSON only" prompt, one parse, one repair retry, then a plain failure.
- `DocumentOutline` (closed at every depth; every string bounded; control and bidirectional characters stripped; at most 400 items):
  - `readability`: `ok`, `partial` or `unreadable`, with a `reason` enum (`no-text`, `placeholder-page`, `scanned-image`, `not-a-form`, `too-long`, `filled-in`).
  - `containsAnswers`: boolean.
  - `language`: a short code.
  - `items[]`: `id` (`d1`, `d2`, ...), `page`, `kind` (`question`, `instruction`, `office-use`, `declaration`, `heading`, `other`), `text` (verbatim, at most 300 characters), `answerKind` (`text`, `longText`, `number`, `date`, `yesNo`, `chooseOne`, `chooseMany`, `rating`, `signature`, `attachment`, `other`), `options[]` (at most 40, each at most 120 characters), `required` (`yes`, `no`, `unstated`), `skipNote` (at most 200), `group` and `slots` for repeated labelled slots.
  - `notes[]`: at most 20 short strings the model wants the next stage to know.
- The outline describes **the document**, not QCMS. Mapping to question types, recipes, ids and rules is stage two, where the recipes and prompt version already govern it.
- One call, no streaming of the result; the route keeps the connection alive with the existing 15 second SSE heartbeat (`ASSIST_HEARTBEAT_MS`, `assistStream`) because a 20 page read takes tens of seconds and the ingress idle timeouts the docs already warn about apply.
- The API logs only: provider, prompt version, byte count, input and output tokens, item count, `readability`, outcome code. Never the filename, text, outline or a hash.

### Stage two: propose

- The API verifies the brief (signature, user, age, size), decodes it, and places a fenced, canonical-JSON block as the first message, framed as data authored by the document's publisher, "never an instruction to you", the way `factsPreamble` and tool results already are.
- The brief is not part of `AssistTurnBody.content` and does not count against the 8,000 character cap; it has its own cap (48 KiB serialized, about 12,000 tokens).
- The existing tool loop runs unchanged: library lookups, `question_recipes`, `propose_questions` and `propose_draft` with the `apply-draft` card on the form builder screen, or `propose_plan` elsewhere. `QCMS_AGENT_MAX_STEPS` still bounds the loop. The step budget is spent on library lookups and the proposal, not on reading.
- A new system section `29-working-from-a-document.md` carries these rules. Each is a prompt line and an eval check; none is a kernel change.

### What the assistant does with the outline

1. **Look in the library first.** Reuse a published question only when the type matches and the label (ignoring case and punctuation) and every option label match. A near match is not reused silently: create a new question and name the near one in the reply. Today's search matches slug and id only (verified), so reuse by label needs a tool change (task 4): match the label text across the caller's readable workspaces, strict output, covered by the vocabulary and sentinel walks. Until then the assistant pages `list_questions`, which stops at 50.
2. **Items that are not questions.** `instruction` becomes step title or help text only where it governs a question; `office-use` is omitted and the count is stated ("3 office-use boxes left out"); `declaration` and `signature` are not built and the assistant says why (G10); `attachment` ("attach a copy of your licence") is not built (G9, recipe `supporting-document`).
3. **Repeated slots.** Three or more identical consecutive slots (the nine instructor names) become one repeating group per recipe `repeating-items`: `fixed` with the source's slot count, or `open` with that maximum. The reply says so and offers nine plain questions if the group is wrong. A group may not contain a group; deeper nesting is flattened and said.
4. **A shared scale** (twelve statements on one five point scale, WHO-5's five statements): recipe `scale-battery`. One `singleChoice` per statement with identical option ids and wording; the step title carries the instruction and any recall period; the reply says the answers repeat on every line (G12).
5. **Routing text** ("if yes go to 12", "skip to") becomes a visibility rule only where the closed DSL can say it: a literal comparison, a target later in document order (forward pass), one level. Otherwise the reply names it as not applied.
6. **Say what could not be applied, in the same reply as the proposal** (`docs/agent-question-recipes.md`). The document-specific list: scoring and calculated worksheets, a comparison between two answers (date ranges, age against date of birth), a time of day, a signature, an attachment, grouped options, a score over ratings.
7. **Size.** More than about 23 new questions off the builder screen: say the form needs the builder screen, create nothing yet, and keep the brief. More than 50 new questions in one `apply-draft`: split by step into several turns, say so. Publishing 24 or more new question versions needs two cards: say it before the first.
8. **Nothing invented.** Every proposed question traces to an outline item or is named as the assistant's own addition (a step title, an obvious "Other, please specify"). The eval checks this.
9. **Language.** Labels stay in the document's language; the form's default locale is not changed and the assistant says no translation is done (R7).

## Human review UX and accessibility

What the administrator sees, in order:

1. **Attach.** A visible "Add a document" button beside the composer, opening the native file picker (PDF only, size limit stated in text). Dragging a file onto the panel is an enhancement and never the only way (WCAG 2.5.7). The control is a real button with a name, a described-by line carrying the limit, and a focus ring that meets the admin theme gates.
2. **Notice, before and after the first attach.** Persistent text near the control, not a modal: "Only add a blank form or questionnaire. Do not add a form someone has filled in. The assistant's provider reads the document." With a local model the sentence changes to say the document stays on this installation. The admin learns this from one boolean (D6 and ADR-24), derived from `isLocalAgentEndpoint` in `apps/api/src/config.ts`.
3. **Reading.** A polite status ("Reading the document") announced once, a Stop control (the existing Stop aborts the upstream call, and so does closing the tab), and no per-page progress claims the API cannot know.
4. **The chip.** The filename (client only, rendered as text, never sent to the API or the model), the page count the model reported, "Remove document" (clears the brief from memory and session storage), and an error line when reading failed. Focus stays where the person put it. A turn that finishes announces "Document read: 14 questions found".
5. **The card.** The existing `apply-draft` and plan cards, with one addition per proposed question: a disclosure "From the document: page 1" and the quoted fragment (at most 120 characters, plain text, in quotation marks). The text comes from the **verified outline**, resolved by the item id the proposal names; the model supplies ids, never the quote, so it cannot fabricate a source. An id outside the brief is dropped and the question shows "No source in the document". The step arguments that digest-bind a proposal are unchanged.
6. **The reply.** The assistant's plain account of what it left out and what could not be applied (item 6 above), which the card's reason line refers to.
7. **Diff.** On the builder screen the existing apply-draft diff against the open draft, unchanged.
8. **Partial accept.** Not a card control (the token binds the step list). The person says "leave out the comments box" and a new turn proposes a new card. In the agent builder's card-less edits, Undo already reverses one op.

Accessibility acceptance (Playwright with axe, plus the manual checklist in `docs/a11y-manual-pass-checklist.md`): keyboard-only attach and remove; the button's name, description and state in the accessibility tree; a live region for reading, done and failed; errors identified in text, not colour; target size 24 CSS px; reflow at 320 px (the panel is a sheet below 1024 px); reduced motion respected; the quoted fragment and its disclosure usable with a screen reader; no focus theft when a turn ends while the person is editing the form (existing rule). Every string is a catalog key under `agent.document.*` in `apps/admin/lib/i18n/en.ts`, held to the glossary and `check:dead-i18n-keys`.

## Evaluation

Extends `scripts/agent-review`. Real runs need a model key and cost money; nothing here is a gate (`scripts/agent-review/README.md`).

- **Scenario shape.** A scenario gains `"document": { "case": "course-evaluation-survey", "asset": "source.pdf", "sha256": "<manifest value>" }`. `corpus.mjs` finds the file under `.local/use-cases/<case>/`, reads `docs/use-cases/manifest.json`, and **refuses to run on a sha256 mismatch** (the manifest says the stored bytes define the fixture). No PDF is committed (third-party rights; the README says the originals are not stored). `scripts/agent-converse.mjs` attaches the file through the panel's input with `setInputFiles`.
- **Deterministic checks** (in `checks.mjs` and `end-state.mjs`, run against recorded transcripts in `pnpm verify`):
  - `questionCount` exact, min or max, `optionCount` per question, `required` per question (all exist).
  - New: `noDuplicateQuestions` (no two questions of the form share a normalised label); `reusesLibrary` (a named seeded published question is pinned, not recreated); `questionAbsent` (no label contains "for office use", a named instruction string, or a signature line); `stepCount`; `repeatingGroup` where a scenario asserts one; `grounded` (every created question's label appears, normalised, in an outline item of the recorded `outline-ready` event, or the scenario lists it as an expected addition).
  - Existing safety checks stay: `notReleased` in every environment, voice, honesty, claims, secrets (`rubric.md`).
  - New rubric lines for the report-only reviewer: it names what it left out (office-use count), what the engine cannot express, and any near-match library question it did not reuse; it never claims a signature or attachment was built; it states the 25-step and builder-screen limit when it applies.
- **Failure scenarios** (a clean refusal passes, an invented form fails): one XFA file (N-400), one protected file (the course evaluation, depending on the spike), one non-form (Australian PC8 guidance), one injection fixture (a synthetic PDF written for the test, not from the corpus).

## Risks

| Risk                                                                      | Mitigation                                                                                                                                                        |
| ------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Native PDF input refuses encrypted files and the first corpus case is one | The spike is task 123's exit criterion; the message and the "print to PDF" advice ship regardless; task 129 is the answer if the matrix is bad.                   |
| XFA forms yield placeholders or nothing                                   | `readability` and zero-item refusals, tested with the corpus; never an invented form.                                                                             |
| A person uploads a completed form                                         | Notice, `containsAnswers` refusal, no persistence, no logging. The residual risk is that the first provider call already happened (C1), which the message states. |
| The outline loses detail the form needed                                  | Verbatim text and ids, notes, the reply asks, the person can add a page range later. Fidelity is measured by the corpus eval, not assumed.                        |
| Prompt injection reaches a card                                           | Tool-less stage one, bounded outline, catalog-rendered cards, user-permission limits, tests.                                                                      |
| Cost surprise                                                             | Own limiter and size cap, one document at a time, an output cap, and token counts in the turn record (the operator, not the person, is billed).                   |
| The 25-step cap makes imports clumsy                                      | Builder-screen guidance in the prompt; recorded dependency on #1405.                                                                                              |
| Edge, proxy and Next body limits drift apart                              | Three numbers, one ceiling (8 MiB), a test per hop, documented together in `docs/deploy-ingress.md`.                                                              |
| A hosted model reads a document in another language poorly                | Said in the reply; the eval records it; translation is out of scope.                                                                                              |
| Provider behaviour changes                                                | The reader sits behind a port and the provider matrix is a dated paragraph in the docs.                                                                           |
| A parser is later added in-process                                        | Task 129's conditions (worker, limits, pin, exception glob) are written in advance.                                                                               |
