Component gaps - design requests

What the overview already defines is marked done; the rest is what the QCMS Design System still needs before the admin build (tasks 032-035) consumes it. Requested by the PO seat, 2026-07-30. Constraints for every component: tokens only (051 contract), WCAG 2.2 AA (AAA in HC), visible focus, 24px minimum targets, works in light / dark / HC.

Buttons

  • Done: primary + ghost at rest/hover, 48px portal scale, weight 600, icon gap.
  • Secondary and destructive variants.
  • Full state matrix: focus-visible, active, disabled, loading.
  • Sizes: small, icon-only; and a density axis (admin runs the same language at 40px).

Inputs

  • Done: field label style.
  • Text, search, select, textarea, date - full anatomy: label + hint + error message + required marker.
  • States: default, hover, focus, error, disabled, readonly.
  • Error pattern feeds task 048 (author validation messages) - design the field-level error and the page-level error summary together.

Alerts / banners

  • Done: one success alert (icon slot, subtle surface, colour-mix border).
  • The severity family: info, warning, danger siblings of the same anatomy.
  • Dismissible and with-action variants; page-level vs field-level scale.
  • Toast (transient) treatment.

Data table (admin)

  • Header with sort states; row hover and selection; striping vs hairline choice.
  • Pagination; empty state; loading skeleton.
  • Density: 44px rows, tabular figures for numeric columns.

Overlays and feedback

  • Confirm dialog - including the destructive confirm (retire / erase flows).
  • Dropdown menu; tabs; breadcrumb.
