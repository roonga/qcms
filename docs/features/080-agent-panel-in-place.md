## Context

Phase A is the plan's "polish in place": the builder's panel becomes the panel the later phases mount on every screen, without yet moving it anywhere. **Half of it has landed.** PR #1076 shipped the compact header with icon buttons, the chat bubbles with in-place streaming and a caret, the in-house safe Markdown subset (`apps/admin/lib/forms/assist-markdown.ts`, rendered by `apps/admin/components/forms/assist-markdown.tsx`), the plain-language step timeline with the API's `tool-outcome` event, the rationale stated once, the proposal as one card, `no-transform` and `x-accel-buffering: no` on the BFF hop (streaming improvement 5), and system prompt version 3 asking for a sentence before the first tool call (improvement 2). The plan names the renderer as `apps/admin/lib/agent/markdown.tsx`; it landed under `lib/forms/` and this task does not move it.

What has not landed is the part that makes a turn visibly alive from its first second and the composer usable: `handlePart` still drops `tool-input-start` into its `default` branch (`apps/api/src/features/forms/assist/assistant.ts`), so a timeline row still appears only once the SDK has parsed a complete tool call, and `propose_draft` carries a whole `FormDefinition`; every text delta still folds into one `rationale` with no segment id; there is no heartbeat; the composer is still a single-line `TextField` with no Stop; and a proposal's arrival still moves focus unconditionally (`assist-panel.tsx`, `headingRef.current?.focus()` on every proposal), which section 4.4 names as the behaviour that would yank a docked user out of the page once phase C docks the panel. This task is the remainder of phase A, and nothing more.

## Deliverables

- **Streaming improvement 1: announce a step when its input starts.** `handlePart` maps the SDK's `tool-input-start` part to the existing `status` event with the tool name and the per-turn step ordinal that `tool-outcome` already keys on, so the timeline row appears while the model is still streaming the call's JSON. An unknown tool name emits nothing, and the refusal is still recorded off the parsed `tool-call`, as today; the loop still ends at that step (issue #814).
- **Streaming improvement 3: keep text segments.** The SDK's text segment ids travel as `{ type: "text", delta, segment }`, so prose segments interleave with timeline rows in arrival order and the draft card's rationale is the last segment rather than the fold of every delta. `apps/admin/lib/forms/assist-turn.ts`, which already builds the turn's segment column, consumes the id instead of inferring boundaries.
- **Streaming improvement 4: heartbeat.** An SSE comment line every 15 seconds during a silent stretch, so an ingress idle timeout does not cut a turn. The admin parser already skips frames with no `data:` line; a test pins that it still does.
- **Improvements 2, 5 and 6, confirmed rather than rebuilt.** The prompt's working order is checked against section 9's wording (one sentence on what you are about to do; tools, with a short note when the plan changes; then the explanation) and `SYSTEM_PROMPT_VERSION` is bumped only if the text moves. The BFF headers from PR #1076 stay. Token counts stay logging only and never reach the screen.
- **The composer and Stop** (section 4.3). A multi-line text area replaces the single-line field: Enter sends, Shift+Enter is a newline. A **Stop** button sits in the composer while a turn runs and aborts the request, which aborts the upstream provider call exactly as the handler's existing abort path does.
- **Focus** (section 4.4). Opening the panel moves focus to the composer. A turn ending moves nothing. A card arriving moves focus to its heading **only when focus was already inside the panel**. After Accept or Discard, focus moves to the card's result line, which stays in the conversation as a record. Escape behaviour beyond today's tooltip dismissal is phase C's, because it needs the top-bar button to return to (Code Owner, 2026-10-24, issue #1133).
- **Reduced motion** (section 4.6), asserted: under `prefers-reduced-motion: reduce` the caret is a static bar, the working indicator has no shimmer and a running timeline row shows an icon, not a spinner. PR #1076 added the media query; this task adds the test that keeps it.
- **The Markdown renderer's hostile-input set, completed.** `assist-markdown.test.tsx` covers HTML tags, image syntax and `javascript:` links today. It gains the remaining classes the plan names: reference-style links and nested emphasis bombs, plus the link rule (Code Owner, 2026-10-24, review finding B3): a link renders as a link only when its path matches an admin **page** route on a closed list, with no query string and no fragment, and as plain text otherwise. It is never a route handler, so a link cannot start the `forms/[formId]/export` download (`apps/admin/app/(shell)/forms/[formId]/export/route.ts`), which only an export card may start (083, D4). This task ships the closed list as a constant beside the renderer, holding the `(shell)` page patterns present at landing. 082 replaces it with its screen table and deletes the constant. No test may pass by emitting raw HTML, an image, an external link or a link to a route handler.
- **Tests this phase owns** (section 14): `handlePart` mapping tests for `tool-input-start` and segments; the heartbeat; the stream parser's new event shape; `assist-turn`'s interleaving; panel tests for Enter, Shift+Enter, Stop and each focus rule; Playwright in `apps/admin/e2e/agent-assist.pw.ts` against the fake provider's new `narrate-then-tools` script: prose and a running step row visible before the first tool result arrives, Stop ending a turn, reduced motion emulated, and axe over a streaming turn.
- **Documentation and the mirror.** `docs/agent-authoring.md` section 6 ("How a turn actually runs") describes the event order as it now is; `apps/api/src/features/forms/assist/README.md` lists the new script; `pnpm qcms:sync-templates` and a `create-qcms-app` changeset, as PR #1076 did.

## Exit criteria

1. With `#qcms-fake:narrate-then-tools`, Playwright sees a sentence of prose and a timeline row in the running state before the first tool result is rendered, and a `handlePart` unit test shows the row's `status` event is emitted from `tool-input-start`, before the `tool-call` part.
2. An unknown tool name on `tool-input-start` emits no event, the parsed `tool-call` is still refused, the turn ends at that step with no proposal, and every `rogue-*` script still produces nothing (041's exit criterion 4 stays green).
3. Text deltas carry a segment id, two prose segments separated by a tool step render as two bubbles in order with the step row between them, and the draft card's rationale is the last segment.
4. During a scripted silence the API emits an SSE comment at the 15 second mark and the parser yields no event for it.
5. Enter sends, Shift+Enter inserts a newline, and Stop aborts both the browser request and the upstream call, asserted on the panel and at the handler.
6. A proposal arriving while focus is outside the panel leaves focus where it was; arriving while focus is inside, it moves to the card heading; Accept and Discard each move focus to the result line.
7. The Markdown tests cover all five hostile classes and assert that no case renders an element, an image or an external link. They also cover the link rule: `[x](/forms/frm_x/export?format=csv&shape=wide)`, `[x](/forms/frm_x/export)`, `[x](/assist)`, `[x](/forms/frm_x/assist)` and a page path that carries a query string each render as plain text, and a page path on the closed list renders as a link.
8. Under emulated reduced motion no animation runs on the caret, the indicator or a running row; axe is green over a streaming turn.
9. 041's fake-provider e2e (propose, accept, publish through the unchanged human flow, walk the branch) and the sentinel test in `assist.integration.test.ts` stay green with the new events on the wire.
10. `pnpm check:templates` passes and a changeset is present.
